Privacy Policy

How BetterAsk handles human profile data and what we collect. Effective March 20, 2026.

What Data We Collect

Human Profiles

  • Understanding scores — numerical scores (0-100%) measuring how well an agent understands its human across 12 life domains
  • Domain coverage — which life domains have been explored (career, relationships, health, etc.)
  • Conversation history — the questions asked by agents and answers provided by humans through the agent
  • Profile metadata — creation dates, update timestamps, question counts

API Usage Data

  • API keys — unique identifiers for each agent/developer account
  • Usage metrics — number of API calls, rate limiting data, subscription tier information
  • Performance data — which questions work best, understanding score improvements

What We DON'T Collect

We don't collect data directly from humans. Agents send us what they know about their humans. We never interact with the human directly — we're a B2B service for AI agents and their developers.

  • No direct contact information (emails, phone numbers, addresses)
  • No financial information
  • No device information or tracking pixels
  • No cookies — we don't use them
  • No analytics on the API — no tracking your usage patterns beyond rate limiting

How Data Is Stored

  • Database: SQLite database hosted on Railway infrastructure
  • Encryption: Data encrypted at rest using Railway's standard encryption
  • Access: Each API key can only access profiles it created — complete isolation between different agents
  • Retention: Profiles persist until explicitly deleted. API keys persist until deactivated.

Data Sharing Policy

We do NOT sell, share, or provide access to human profile data to any third party. Each API key can only access profiles it created. This data isolation is enforced at the database level.

  • No third-party analytics or tracking
  • No data brokers or advertisers
  • No sharing for marketing purposes
  • Customer data stays with the customer who created it

Agent/Developer Responsibility

The agent or developer using BetterAsk is responsible for:

  • Informing their human that BetterAsk is being used to improve understanding
  • Obtaining consent for sharing human data with BetterAsk
  • Explaining what data is being shared and how it's used
  • Respecting human preferences about data collection and retention

Suggested Consent Flow for Agents

We recommend agents introduce BetterAsk to their humans like this:

"I'd like to understand you better over time so I can be more helpful. I use a service called BetterAsk that helps me ask the right questions and tracks how well I understand you across different areas of your life (like your career, relationships, health, and goals). Your answers help me improve. You can ask me to show your understanding score anytime, and you can request all your data be deleted at any point. Is that okay with you?"

This approach:

  • Explains what BetterAsk does in human terms
  • Makes data usage transparent
  • Gives the human control and choice
  • Sets expectations for ongoing data collection

Your Rights

Right to Deletion

  • Endpoint: DELETE /profile/{human_id}
  • Timeline: Complete data removal within 24 hours
  • Scope: Removes all profile data, conversation history, and understanding scores

Right to Export

  • Endpoint: POST /profile/{human_id}/export
  • Format: Complete JSON export of all stored data
  • Portability: Take your data anywhere

Right to Audit

  • Endpoint: GET /privacy/{human_id}
  • Shows: Exactly what data is stored, when it was collected, and how it's been used
  • Transparency: No hidden data collection

GDPR Compliance

BetterAsk follows GDPR principles:

  • Data minimization — we collect only what's needed for understanding improvement
  • Purpose limitation — data is used only for agent-human understanding improvement
  • Right to erasure — delete all data via API endpoint
  • Right to portability — export all data in machine-readable format
  • Consent-based processing — agents must obtain human consent

Security

  • API key authentication for all data access
  • Data isolation — each API key can only see its own data
  • Encryption at rest via Railway platform
  • No plaintext storage of sensitive profile information
  • Rate limiting to prevent abuse

  • The most current version is always available at betterask.dev/privacy
